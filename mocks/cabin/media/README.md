# mock-cabin 曲库目录

往这里丢音频文件，车机端就能把它们放出来。

## 两种形态，出声位不在同一台机器上（M63）

| 形态 | 谁出声 | 什么时候是它 |
|---|---|---|
| **车机端认领**（常态） | cockpit 客户端：经网关拉走曲目字节，用 rodio 自己解码播放 | 只要车机端起着并认领了出声位（`/health` 的 `clientSinks` ≥ 1） |
| **服务端后端**（单机 demo） | mock-cabin 进程自己 spawn `mpg123` / `afplay` | 没有任何车机端认领时的兜底 |

两条互斥：端认领的那一刻服务端后端立刻停，租约（5 秒）过期后再退回去。

**部署之后只有第一种成立**——mock-cabin 住在服务器的容器里，那里既没有 mpg123
也没有声卡，装上也没用：响的是服务器，而车主在车里。所以
`MOCK_CABIN_AUDIO` 与下面这些关于播放后端的说明，**只对单机 demo 那一种形态有意义**。

## 演示素材：两条路，不要去找歌

```bash
corepack pnpm demo:music      #  9 首真实录音（下载，CC0）
corepack pnpm demo:media      # 13 条本地合成（10 儿歌 + 3 故事）+ 时长 sidecar
```

| 组 | 怎么来的 | 为什么是这条路 |
|---|---|---|
| `肖邦（Musopen CC0）` 9 首 | 从 archive.org 下 Musopen 的 CC0 录音 | **真人钢琴演奏**。器乐最听得出合成痕迹，而它恰好有出路：公有领域的真实录音可以用 |
| `CarLife 故事` 3 篇 | 项目自己的阿里云档 TTS（`qwen3-tts-flash`）合成 | 本机 `say` 是十几年前的系统 TTS，机器味是固有属性；而这个项目自己就接着神经网络 TTS |
| `CarLife 童谣` 10 首 | 本文件的加法合成器（正弦波叠泛音） | **听着像音乐盒，不像唱的**。唱出来的儿歌几乎都还在版权期内，免费的真录音找不到——见下 |

「不下商业音乐」不等于「只能自己合成」：**CC0 的真实录音是可以用的**。
逐条来源与许可证在 [`PROVENANCE.md`](PROVENANCE.md)（那份入 git，音频不入）。

### 儿歌为什么还是合成的

找过了，结论是**没有可靠的免费真录音**：archive.org 上标 public domain 的儿歌基本两类——
上传者自己勾的（实际是 1996 年商业 CD 之类，那个标注不可信），或者 78 转老唱片
（年代够老的确实 PD，但是英文、留声机音质，且要逐条核出版年份）。
唱出来的儿歌绝大多数仍在版权期内。所以这 10 首诚实地留作合成占位，
名字里的「CarLife 童谣」就是它的标注。

生成器同时写一份 `library.json` 补时长：`probeDuration` 先试 `afinfo` 再试 `ffprobe`，
而 mock-cabin 跑在 Alpine 容器里，**两个都没有**，不补的话每一首的 `durationSec` 恒为 null。

⚠️ **那三篇故事是人声**。哨兵开着时放它们有误唤醒的风险（见下面「选曲注意」），
演示唤醒功能时用肖邦那九首或童谣。

## 加一首歌

```bash
cp ~/Downloads/"某某 - 江湖天涯客.mp3" mocks/cabin/media/
curl -sX POST localhost:8793/media/library | jq '.tracks[].title'   # 重扫，不用重启服务
```

文件名就是元数据，约定 **`艺人 - 曲名.mp3`**（按第一个 ` - ` 拆，曲名里的连字符保得住）。
没有 ` - ` 就整个文件名当曲名、艺人为 `null`。

`trackId` 由文件名派生（`t-` + sha1 前 8 位），加歌删歌都不会让已有 id 漂移——
所以点歌点的是哪首就是哪首，不像序号那样会错位。

## 版权：这个目录不入 git

`.gitignore` 把所有音频挡在仓库外，只有那首程序合成的垫底曲例外。
**别把商业发行的音乐提交进来**——私有仓库也是分发。演示机上各自放本地文件即可。

## 格式

首选 **mp3**。原因是播放后端优先用 `mpg123`（它只解 mp3/mp2），而它是唯一能做到
「暂停可续播 + 播放中改音量 + 有进度」的那个；退到 `afplay` 的话，改音量要下一首才生效。

放别的格式也行（afplay 后端支持 m4a/wav/flac 等），但 `GET /media/library` 会把
`playable: false` 和原因一起报出来。转一下即可：

```bash
ffmpeg -i "艺人 - 曲名.flac" -b:a 192k "艺人 - 曲名.mp3"
```

## 选曲注意：**别放有人声的**

车机端的语音哨兵一直在听。有人声的歌会被 ASR 转写，歌词里出现「暖暖」的同音近音
就会**误唤醒**（`voice/wake.rs` 的判定是拼音归一后同音计命中）。
TTS 播报期间靠 `TTS_PLAYING` 丢帧，但音乐要连放几分钟，不能全程丢帧——
否则放歌时就叫不动助手了。所以现场用纯器乐。

## 覆盖元数据（可选）

曲名里本来就带 ` - `、或想手写时长，放一份 `library.json`：

```json
{
  "某某 - 江湖天涯客.mp3": { "title": "江湖天涯客", "artist": "某某", "durationSec": 248 }
}
```

按文件名索引，只覆盖写了的字段。JSON 打错字不会让曲库变空（会整份忽略）。

## 目录换个地方

`MOCK_CABIN_MEDIA_DIR=/path/to/music` 指到别处，默认是本目录。

容器形态下本目录是**只读挂进去**的（`infra/docker-compose.stack.yml`），
不进镜像——音频不入 git，靠镜像发曲库这条路本来就走不通。

## 相关环境变量

| 变量 | 默认 | 作用 |
|---|---|---|
| `MOCK_CABIN_MEDIA_DIR` | 本目录 | 曲库目录 |
| `MOCK_CABIN_AUDIO` | 自动探测 | `off` 静音（测试用）；`mpg123` / `afplay` 强制指定后端，用来验证降级表现 |
| `MOCK_CABIN_AUDIBLE_ZONE` | `cabin` | 哪个媒体分区真的出声（主机只有一对喇叭） |
